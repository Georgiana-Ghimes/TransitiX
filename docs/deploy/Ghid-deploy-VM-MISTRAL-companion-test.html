3. Fișiere env — ce schimbi

Pe un folder dedicat e cel mai simplu: totul în server/.env (fără dansul COMPANION=1 / .env.companion). UI-ul companion se bake-uiește la npm run build:companion din modul Vite, nu din acest env. 

cp server/companion.env.example server/.env
nano server/.env   # sau vim / code

3.2 CLIENT_ORIGIN — alege una

Cum testeziExemplu CLIENT_ORIGINTRUST_PROXY
Din LAN, pe IP:port http://192.168.x.x:3003 nu seta (sau 0)
Doar pe VM (localhost) http://127.0.0.1:3003 nu seta
HTTPS prin Cloudflare tunnel https://documente-mistral.domeniul-tau.ro TRUST_PROXY=1
UI pe Vercel + API pe tunnel https://….vercel.app (+ opțional și hostname-ul tunnel) TRUST_PROXY=1
Dacă deschizi app-ul pe un host/port pe care CLIENT_ORIGIN nu îl listează, login / cookie / reset pot eșua. Poți pune mai multe origini separate prin virgulă dacă codul din proiect le acceptă pe listă — pentru test, ține una, aceeași pe care o tastezi în browser.

6. Pornire persistentă (systemd)

sudo tee /etc/systemd/system/transitix-mistral.service > /dev/null <<'EOF'
[Unit]
Description=Transitix companion MISTRAL (test)
After=network.target docker.service
Requires=docker.service

[Service]
Type=simple
User=YOUR_USER
WorkingDirectory=/home/YOUR_USER/apps/transitix-mistral/server
Environment=NODE_ENV=production
# .env e citit de loadEnv din WorkingDirectory
ExecStart=/usr/bin/node src/index.js
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

# Înlocuiește YOUR_USER, apoi:
sudo systemctl daemon-reload
sudo systemctl enable --now transitix-mistral
sudo systemctl status transitix-mistral --no-pager

După git pull + schimbări UI: rulezi din nou npm run build:companion din root-ul proiectului, apoi sudo systemctl restart transitix-mistral.

7. Cloudflare Tunnel (HTTPS) — ai deja cloudflared pe VM

Recomandat pentru test: un hostname nou pe același tunnel pe care îl folosești deja pentru companion-ul vechi. Cloudflare dă certificatul; pe VM rămâne http://127.0.0.1:3003. Nu deschizi port inbound.

7.1 Vezi ce rulează acum

sudo systemctl status cloudflared --no-pager
# sau, dacă e rulat din user:
systemctl --user status cloudflared --no-pager

# Config tipic:
ls -la ~/.cloudflared/ /etc/cloudflared/ 2>/dev/null
sudo cat /etc/cloudflared/config.yml
# sau: cat ~/.cloudflared/config.yml

cloudflared tunnel list

Notează tunnel: (nume sau UUID) și hostname-ul existent (ex. documente.domeniul-tau.ro → http://127.0.0.1:3002).

7.2 Adaugă DNS pentru instanța MISTRAL

Pe același tunnel (înlocuiește numele tunnelului și domeniul):

# Exemplu: tunnelul existent se numește transitix-rai
cloudflared tunnel route dns transitix-rai documente-mistral.domeniul-tau.ro

# Verifică în Cloudflare Dashboard → DNS: CNAME documente-mistral → <tunnel-id>.cfargotunnel.com

7.3 Extinde config.yml cu al doilea ingress

Păstrează ruta veche; adaugă una nouă deasupra catch-all-ului http_status:404:

tunnel: transitix-rai
credentials-file: /root/.cloudflared/<TUNNEL-UUID>.json

ingress:
  # Instanța VECHE (neschimbată)
  - hostname: documente.domeniul-tau.ro
    service: http://127.0.0.1:3002
    originRequest:
      disableChunkedEncoding: false
      connectTimeout: 30s

  # Instanța NOUĂ MISTRAL (test)
  - hostname: documente-mistral.domeniul-tau.ro
    service: http://127.0.0.1:3003
    originRequest:
      disableChunkedEncoding: false
      connectTimeout: 30s

  - service: http_status:404
Ordinea contează: hostname-urile specifice înainte de http_status:404. Path-ul credentials-file rămâne al tunnelului tău existent (nu inventa alt UUID).

7.4 Actualizează server/.env pe instanța MISTRAL

CLIENT_ORIGIN=https://documente-mistral.domeniul-tau.ro
TRUST_PROXY=1

Apoi:

sudo systemctl restart transitix-mistral

8. Vercel pe link-ul Cloudflare (frontend pe Vercel, API pe VM)

Context: clientul apelează /api/… și /uploads/… pe același origin (URL relative). Pe Vercel trebuie rewrite către hostname-ul Cloudflare al API-ului de pe VM. Alternativa mai simplă: fără Vercel — deschizi direct https://documente-mistral… (API-ul servește deja dist/).
Dacă tot ce vrei e „un link HTTPS de test”, oprește-te după §7. Vercel are rost când vrei preview-uri / deploy UI separat de API.

8.1 Pregătire pe VM (API rămâne sursa de adevăr)

  • Tunnel Cloudflare (§7) trebuie să răspundă pe https://documente-mistral.domeniul-tau.ro/api/health.
  • În server/.env, CLIENT_ORIGIN trebuie să includă URL-ul Vercel:
# După ce știi domeniul Vercel (ex. transitix-mistral.vercel.app):
CLIENT_ORIGIN=https://transitix-mistral.vercel.app,https://documente-mistral.domeniul-tau.ro
TRUST_PROXY=1

sudo systemctl restart transitix-mistral

Dacă autentificarea acceptă o singură origină, folosește doar URL-ul Vercel în CLIENT_ORIGIN când testezi prin Vercel.

8.2 Fișier vercel.json în rădăcina repo

cat > vercel.json <<'EOF'
{
  "buildCommand": "npm run build:companion",
  "outputDirectory": "dist",
  "framework": null,
  "rewrites": [
    {
      "source": "/api/:path*",
      "destination": "https://documente-mistral.domeniul-tau.ro/api/:path*"
    },
    {
      "source": "/uploads/:path*",
      "destination": "https://documente-mistral.domeniul-tau.ro/uploads/:path*"
    },
    { "source": "/((?!api/|uploads/).*)", "destination": "/index.html" }
  ]
}
EOF
Înlocuiește hostname-ul cu domeniul tău real din §7. Fără rewrite-uri, login-ul pe Vercel lovește 404 pe /api.

8.3 Creează proiectul în Vercel (UI)

  1. Intră pe vercel.com → Add New → Project
  2. Import repo-ul Georgiana-Ghimes/TransitiX
  3. Root Directory: rădăcina repo (nu server/)
  4. Framework Preset: Other (build-ul e din vercel.json)
  5. Branch de producție: MISTRAL-experimenting-rai-documents
  6. Nu pune pe Vercel MISTRAL_API_KEY / DATABASE_URL — OCR și DB rămân pe VM
  7. Deploy

8.7 Limitări

  • Upload / OCR foarte lung: timeout proxy Vercel poate tăia; pentru dosare grele folosește direct hostname-ul Cloudflare (§7).
  • Push pe branch → Vercel rebuild UI; pe VM: git pull + migrate + restart API.
  • Variantă curată: pe VM doar API; pe Vercel doar UI; tunnel Cloudflare expune :3003.

11. Ce să nu faci

  • Nu folosi același JWT_SECRET / aceeași DB ca instanța veche.
  • Nu rula seed pe o bază cu date reale de client.
  • Nu deschide :5436 / :3003 spre internet dacă ai tunnel — lasă-le pe localhost.
  • Nu pune TRUST_PROXY=1 fără Cloudflare (sau alt proxy) în față.
  • Nu da oamenilor un link de quick tunnel (*.trycloudflare.com efemer).
  • Nu uita să actualizezi CLIENT_ORIGIN când schimbi între Cloudflare-only și Vercel.
