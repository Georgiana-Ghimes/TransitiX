ACELAȘI HASH pe ambele branch-uri backup → migrate → build → restart Fără cherry-pick pe ambele
Regula de aur: pe MISTRAL și pe TRANSITIX-RAI-PROD trebuie să fie același commit SHA după merge. Nu face cherry-pick pe ambele — creează două hash-uri și „1 ahead / 1 behind”.
Pe VPS nu folosi npm run dev:companion. Doar pull + deploy-companion.js + servicii (systemd / Caddy).
PC (MISTRAL, test) │ commit + push │ merge --ff-only → TRANSITIX-RAI-PROD │ push PROD ▼ GitHub TRANSITIX-RAI-PROD (același SHA ca MISTRAL) │ ▼ VPS git reset --hard origin/TRANSITIX-RAI-PROD deploy-companion.js (backup → migrate → build → restart) │ ▼ https://rai-transitix.filumforge.ro

A. Pe PC — trimiți codul pe branch-ul de prod

A1. Lucrezi și testezi

  1. Branch: MISTRAL-experimenting-rai-documents
  2. Faci modificările, testezi local (dev:companion pe PC).
  3. Commit + push pe MISTRAL.

A2. Urci pe PROD (același hash)

git checkout TRANSITIX-RAI-PROD
git fetch origin
git merge --ff-only MISTRAL-experimenting-rai-documents
git push origin TRANSITIX-RAI-PROD

# verificare: același SHA
git rev-parse HEAD
git rev-parse MISTRAL-experimenting-rai-documents

git checkout MISTRAL-experimenting-rai-documents
Dacă merge --ff-only eșuează, branch-urile au divergat. Nu forța pe prod până nu înțelegi de ce. Aliniază (merge corect sau reset controlat), apoi verifică din nou SHA-urile.
  • Test ok pe MISTRAL
  • Merge FF pe TRANSITIX-RAI-PROD
  • Push pe origin
  • SHA MISTRAL = SHA PROD

B. Pe VPS — o singură comandă

Conectare:

ssh root@185.137.122.45

Deploy:

cd /opt/rai/TransitiX
npm run deploy:companion:vps

Rulează, în ordine:

  1. git — fetch + checkout + reset --hard pe origin/TRANSITIX-RAI-PROD (actualizează codul; nu mai faci git pull separat — pe VPS reset --hard e mai sigur decât pull)
  2. npm ci — root + server/
  3. deploy-companion — backup → migrate → build → systemctl restart rai-api
  4. caddy reload (best-effort)
  5. health — curl pe /api/health
Dacă un pas eșuează, scriptul se oprește. Nu „jumătate deploy”. Repari, rulezi din nou. Clientul rămâne pe versiunea veche până reușește tot lanțul.
Dacă pe VPS încă lipsește scriptul (cod înainte de build 100): o dată git fetch origin TRANSITIX-RAI-PROD && git reset --hard origin/TRANSITIX-RAI-PROD, apoi npm run deploy:companion:vps.
  • curl health: "ok":true, "db":true, "ocr":"mistral"
  • Browser: https://rai-transitix.filumforge.ro (hard refresh Ctrl+Shift+R dacă UI vechi)
  • Login + o acțiune scurtă (ex. listă avize)
  • Versiunea / build-ul din UI corespunde cu ce ai pus pe PROD

C. Rollback (dacă ceva e greșit)

C1. Rollback cod (păstrezi baza)

cd /opt/rai/TransitiX
git log --oneline -15
# alegi COMMIT_BUN
git reset --hard COMMIT_BUN

# fără git pull; skip-backup dacă ai dump recent
npm run deploy:companion:vps -- --skip-git --skip-backup

Pe PC / GitHub: aliniază TRANSITIX-RAI-PROD (și MISTRAL, dacă e cazul) la același commit.

C2. Rollback date

Restore din /var/backups/rai/ (vezi ghidul mare de instalare, §12). Snapshot Contabo = doar dacă mașina e stricată, nu pentru o greșeală de cod.

npm run db:backup -- --out /var/backups/rai --keep 14

E. Ce NU faci

  • Nu lucra direct pe VPS în fișiere (apoi git pull se încurcă).
  • Nu rula dev:companion pe VPS.
  • Nu face cherry-pick pe MISTRAL și pe PROD separat.
  • Nu deschide în firewall porturile 3002 / 5435 spre internet.
  • Nu comita .env.companion / .env.postgres.

F. Mai târziu — deploy automat (opțional)

Când vrei zero SSH la update: GitHub Actions pe push la TRANSITIX-RAI-PROD, environment RAI-PROD, rulează pe VPS același bloc ca la §B. Până atunci, pașii A + B sunt sursa de adevăr.
