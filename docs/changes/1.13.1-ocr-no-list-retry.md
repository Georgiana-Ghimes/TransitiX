# 1.13.1 — OCR stop pe failed / fără retry la poll

**App:** `1.13.1` · companion `1.9.1` build `65`  
**Date:** 2026-09-30

## Root cause

`GET /api/driver-documents` re-declanșa `extractBatchDocuments` pentru orice rând `uploaded`. Companionul poll-uiește lista la ~8s cât timp există „Se procesează…”, deci fiecare refresh adăuga un job OCR pe aceleași poze. Paddle se aglomera → timeout / down → VM greu. În plus, un OCR întârziat putea scrie câmpuri pe un rând deja marcat Eșuat (birou: „s-a completat fără Re-extrage”). Toast-ul de câmpuri lipsă pornea la fiecare reload.

## Fix

- Fără kick OCR din listă; upload pornește OCR o singură dată; stale → Eșuat
- Commit OCR doar dacă status e încă `uploaded`
- Paddle down → fail imediat pe upload + pe spinner-ele șoferului
- Toast auto doar la tranziția uploaded → extracted cu lipsuri

## VM

1. `git pull` · `npm i` dacă e nevoie · restart API + companion + Paddle sidecar  
2. Rândurile blocate „Se procesează…” ar trebui să treacă la Eșuat (stale sau paddle-down)  
3. Reload companion: fără toast repetat; fără spike nou pe Paddle doar din listă  
4. Re-extrage din birou doar când health OCR e ok (butonul gri = paddle-down)
