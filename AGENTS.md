# AGENTS.md

## Project Context

Transitix is a full-stack TMS (Transport Management System) app.

- Frontend: React + Vite in `src/`
- Backend: Express API in `server/`
- Database: PostgreSQL

## Key Files

- `src/api/client.js` — frontend API client (auth, entities, integrations)
- `src/lib/AuthContext.jsx` — JWT auth state
- `server/src/index.js` — API entrypoint
- `server/src/migrate.js` — DB schema
- `server/.env` — local DB/JWT config (do not commit secrets in production)

## Working Notes

- Run backend with `npm run dev --prefix server` (port 3001)
- Run frontend with `npm run dev` (port 5173, proxies `/api` and `/uploads`)
- Local Postgres: `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d db` (host port **5434**)
- Copy `server/.env.example` → `server/.env` (invented local secrets are fine; no teammate handoff required)
- Prefer existing entity API patterns in `src/api/client.js` before adding new clients
- Keep multi-tenant isolation via `company_id` on all company-scoped queries
- Routing goes through `server/src/lib/geo/osrm.js` — never hand-roll a distance. Unset `OSRM_URL` must stay a 503, not a fallback estimate
- Whole-matrix requests go through `cachedMatrix` in `server/src/lib/geo/matrixCache.js`, not `osrmTable` directly. It keys on the *snapped* node pair, which is why `planFetch` splits a partial miss into thin rectangles — the naive "every dirty row × every dirty column" re-measures the whole matrix as soon as one new point appears, which is exactly when the cache should help
- `mergeTableResponse` never overwrites a node key it already has. One point split across two keys mid-call would file half its pairs where nothing will look for them
- OSRM graph: `npm run osrm:prepare`, then `docker-compose.osrm.yml`. Graph data lives in `docker/osrm/` (gitignored)
- Address parsing/dedupe lives only in `server/src/lib/geo/address.js`. `address_key` is both the dedupe key and the geocode cache key — changing its output invalidates existing `locations` rows and every `geocode_cache` row
- Geocoding confidence is scored in `server/src/lib/geo/matchScore.js` and is provider-agnostic on purpose — every threshold (0.8 accept, 0.45 review, the `/locations` colours) compares those numbers without knowing the vendor. A provider's own score must never be passed through as confidence
- TomTom is an escalation, never the default: `escalatingSearch` only pays when the free provider is under the accept threshold, and a failing paid provider must never break geocoding
- Only a human sets `geocode_verified` — via `/locations`. The geocoder writes coordinates and a confidence, never the verified flag
- Confidence thresholds live in two places on purpose (`server/src/lib/geo/geocode.js` and `src/lib/locationsUi.js`). Change one, change the other, or the screen tells a different story than the batch run
- When comparing street names, use `streetNameTokens()` — comparing raw strings matches "Calea Aradului" to "Calea Torontalului" on the shared type word
- `trips.distance_source` is server-controlled and deliberately NOT in the Trip writable list, so a client cannot claim a value is auto-computed. `manual` is never overwritten
- Trip saves must never depend on OSRM. `refreshTripDistance` is best-effort and swallows every failure — keep it that way
- `telematics_positions` is the history; `gps_logs` with `is_current` is the last-known projection the map already reads. Every ingest (`server/src/lib/telematics/ingest.js`) writes both. Do not delete `gps_logs`
- Provider ingest authenticates with `X-Telematics-Key` (hashed on `companies.telematics_api_key_hash`). The plaintext is shown once on rotate — never store it in the DB
- After a successful ingest, `evaluatePosition` may open `route_exceptions` and cascade ETAs on `intarziere`. Evaluation must stay best-effort: never roll back a stored position. Use `skipEvaluate: true` in unit tests that fake the DB
- Live board events go through `liveHub.publish` (`position`, `exception`, `pod`, …). `GET /api/telematics/stream` is SSE; EventSource auth is `?access_token=` because browsers cannot set Authorization headers
- ePOD lives in `delivery_proofs` (one per route stop). Driver **Gata** / **Nu s-a putut** on delivery stops must go through `POST .../pod`, not a bare status flip — otherwise there is no signature trail
- Historical replay: `GET /api/telematics/replay/:routeId` — planned geometry from OSRM, actual trail from `telematics_positions` for `route_date`. Actual km is haversine on the breadcrumb; do not call OSRM a second time for the realized path
- Loading packer (`server/src/lib/loading/packer.js`): LIFO means later stops pack first (toward the nose). Missing cargo dims fall back to EU 13.6×2.45×2.7 — never invent axle limits; warn only when max kg is set
- Territories (`server/src/lib/geo/territories.js`): capacitated k-means on geocoded locations; polygons are convex hulls, not hand-drawn by default. `POST /territories/generate` with `apply:false` is preview-only and must not write
- Cockpit KPIs: `GET /api/analytics/cockpit` aggregates punctuality, plan-vs-actual km/hours, and cost from `costModel` (vehicle rates falling back to company defaults). No rates anywhere → `cost_total` stays null — do not invent lei defaults
- Route launch: `POST /api/routes/:id/launch` sets `lansata` then requests UIT via `etransport.js`. Three modes: `off` skips, `stub` (default) mints a `STUB-RO…` placeholder, `anaf` calls ANAF for a real code. See the e-Transport rules below — the placeholder marking is not cosmetic
- e-Factura: `GET /api/invoices/:id/ubl` exports UBL 2.1 (CIUS-RO customization id) via `efactura.js`. Never flips `efactura_status` to sent/accepted — SPV upload needs a real certificate later. Health `capabilities.efactura` is `ubl`, not a fake live feed
- Tachograph: `POST /api/tachograph/import` archives `.ddd`/`.tgd`/`.c1b`/`.v1b`, TLV-scans VU (2-byte) or card (3-byte) tags, stores `tachograph_imports`. Status `partial` means type detected — do not invent Reg. 561 violations from raw bytes. Full activity decode is later
- In the entity PUT handler, anything that adds keys to `data` must run before `Object.keys(data)` is taken, or the SET clause and the value list go out of step
- Never put a backtick inside the `migrate.js` SQL template literal — it ends the string and the file stops parsing
- P1 model: an order is planned iff a `route_stops` row references it (partial unique index on `order_id`). `orders` deliberately has no back-pointer, so the two cannot disagree
- `route_stops (route_id, seq)` is UNIQUE DEFERRABLE — reordering rewrites every seq in one transaction
- `trips.route_stop_id` links a generated CMR back to the stop it came from, with a partial unique index. That is what makes "emit CMRs" idempotent, so it is server-controlled and NOT in the Trip writable list, like `distance_source`
- The order import never guesses a location. A line that cannot be matched by name or `address_key` is an error, not a new location — same rule the manual order form enforces
- Romanian decimals in an import: rightmost separator wins when both appear; a lone dot with exactly three digits is thousands. Change `parseNumber` and you change what a weight means
- The road-sheet PDF is rasterized on purpose. jsPDF's standard fonts cannot encode `ș`, `ț` or `ă` — do not "optimise" it into vector text without embedding a font first
- Use `toFiniteNumber` from `src/lib/utils.js` instead of `Number()` when a value may be unset — `Number(null)` is `0` and passes `Number.isFinite`, which has silently produced a wrong value four separate times
- VROOM never talks to OSRM. `server/src/lib/planning/solver.js` hands it a matrix that came from `cachedMatrix`, so every measurement stays on one path and the second run of a day is free. A VROOM container configured with a router would quietly bypass all of that
- VROOM counts in integers: durations in seconds, distances in metres, money in bani, volume in hundredths of a cubic metre. `CAPACITY_DIMENSIONS` is the single place those scales are declared, and the demand vector and the capacity vector must always be built from it
- An unrecorded `capacity_*` on a vehicle becomes the day's total, not zero. Zero would make the vehicle refuse every order, which is not what "nobody typed it in" means
- No cost recorded anywhere means the solver optimizes time and `kpis.cost` stays null. Do not invent a lei-per-km default — a made-up objective produces a plan that looks costed and is not
- `POST /api/planning/solve` stores a proposal in `route_scenarios`; `POST .../promote` is what turns it into routes. Promote must refuse the day if any route is already `lansata` / `in_executie` / `finalizata`
- After VROOM answers, `applyDrivingRules` inserts Reg. 561/2006 breaks (45 min after 4h30 driving) and daily rests (11 h after 9 h driving) as real `pauza` / `repaus` stops — including mid-leg splits. Do not move this into VROOM breaks alone; the post-processor is what keeps the plan legal by construction
- Dispatch board: every action needs a button. Drag-and-drop is a desktop-only enhancement and must never be the sole way to do something
- `vehicle_class` (commercial, e.g. "10t") and `mma_kg` (from the registration) are different things: tariffs key off the class, zone taxes off the MMA. Never substitute one for the other
- Contractual tariffs are versioned by validity period and never edited in place — every lookup is *as of a date* so old reports stay reproducible
- Billable kilometres are the full round trip `garaj → încărcare → descărcare(s) → garaj`, kept per leg in `trip_legs`
- A TPO may cover several trips (`trips.tpo_number` is not unique); several unloading points on one trip is still ONE trip
- Reports use `gross_weight_kg` (goods + pallets), not quantity — quantity and weight are separate columns and must never substitute for one another
- A new document layout is a new profile object in `server/src/lib/ocr/profiles.js`, never a change to the extraction engine
- A profile can only fill a column listed in `EXTRACT_COLUMNS` (`server/src/routes/documents.js`). A field the extractor reads and that list omits is dropped in `toColumns` without a word, so the row keeps its default and the page's own value never arrives — that is what happened to `numar_curse` until the carnet profile was added
- The carnet de bord (`carnet_bord`) is handwriting, and its vocabulary is not the printed aviz vocabulary: `CANT MARFĂ` is not `cantitate`, `NR. CURSE` exists nowhere else, and the route runs onto the line below its label. Before blaming OCR for a blank field, run the text through `extractDocument` — the plate and the TRO code read on any layout, which is exactly why they can improve while everything else stays empty
- OCR confidence is per field, not per document. Never write a field below the reject threshold, and never overwrite anything listed in `corrected_fields` — a human looked at it
- Every aviz is read by **one** extractor: `extractBatchDocuments` in `server/src/routes/documents.js`, over `lib/ocr/readText.js`. There used to be a second one (`avizOcr.extractAvizFromFile` on Google Vision) and the two disagreed about the same row — re-extracting a driver's photo from `/avize` replaced its fields with a stub and nulled the TPO. Do not add a "quick" extraction path for one screen
- A document must belong to a `document_batches` row before it can be read, because the extractor works per batch. `POST /avize/extract` creates one for a fresh upload and attaches one to a row that predates batches
- OCR is **Mistral Document AI** (cloud): `OCR_PROVIDER` is `mistral` or `none`; unset + `MISTRAL_API_KEY` → mistral. No local OCR sidecar. Health reports `mistral` / `mistral-down` / `none`. Google Vision and Paddle were removed
- A PDF with a text layer is read by `pdf-parse` in Node; only image/scanned PDFs hit Mistral. A timeout is not an empty read — `readDocumentText` throws `OCR_TIMEOUT`, `markExtractFailed` is skipped so the document stays in the queue
- Every message a person reads goes through `friendlyErrorMessage` in `src/lib/notify.js`, and callers pass the **error object**, not `err.message` — the string loses the HTTP status, and the status is what tells 401 from 429. `notifyError(title, err)`, never `notifyError(err.message || title)`
- Server messages are written in Romanian, for the operator. A library's wording is not a message: multer's `Unexpected field` becomes "Prea multe fișiere odată. Trimite maximum N…" in `uploadErrorMessage`, and 401/403 always use the status copy because `Invalid or expired token` describes a token rather than a next step
- Limits the client can check are checked on the client first — file count and size before an upload spends a driver's data, and `CLIENT_UPLOAD_MAX` (20/min) in front of the server's 30/min so a 429 is the backstop, not the first feedback
- The blur check in `src/lib/imageQuality.js` warns and never blocks. It is a heuristic, and a document nobody can read still beats a document nobody sent
- TLS is the tunnel's job, never the app's — Cloudflare's edge certificate beats a self-signed one on the VM. What the app owes the arrangement is `TRUST_PROXY`, which is **off by default**: trusting `X-Forwarded-*` with nothing in front lets a client claim any address. HSTS is decided per request from `req.secure`, so localhost never gets pinned to a scheme the dev server does not speak
- `securityHeaders` sets `frame-ancestors` but deliberately no full CSP. The app loads its own bundle, inline styles and blob-URL previews; a policy written without testing them breaks the screen quietly instead of protecting it
- `npm run uploads:prune` removes **orphans only** — files no row in `FILE_COLUMNS` points at, older than a grace period so an upload waiting for its row survives. A referenced file is never deleted whatever its age: `aviz_export_log.snapshot` reproduces the numbers on a sheet, but only the file shows the customer where they came from. Adding a column that stores an upload path means adding it to `FILE_COLUMNS`, or its files become deletable — the script aborts on a column it cannot find, for that reason
- `SHARPNESS_MIN` is calibrated, not guessed: run `npm run dev` and open `/dev/sharpness`, add real avize, mark each Citibil/Neclar, and take the number it suggests. The page runs the same decode, downscale and Laplacian the app runs — a Node script with its own image decoder would scale differently and hand you a threshold that misbehaves in the browser. The route exists only in a dev build (`import.meta.env.DEV`), verified absent from `dist/`
- A document longer than `OCR_INTERACTIVE_MAX_PAGES` (3) extracts in the **background** and `POST /avize/extract` answers `202` with `extraction_pending`. Every page is a full OCR pass, so a scanned dossier held under a spinner would time out on a document that reads perfectly well
- Two OCR budgets in `readText.js`: background (`OCR_TIMEOUT_MS`, default 300 s) and interactive (`OCR_INTERACTIVE_TIMEOUT_MS`, default 120 s for cloud latency). Anything a person waits on passes `interactiveOcrTimeoutMs()`. Page caps / truncation from the provider must never be silent (`pages_truncated`)
- **The provider boundary is two functions.** `runMistralOcr` returns text and `normalizePages` (`lib/ocr/ocrBlocks.js`) turns the provider's `pages[]` into `{page, type, text, confidence, bbox, page_width, page_height}`. Everything downstream — `extracted_data.ocr_blocks`, the HITL overlay, `src/lib/ocrBlocks.js` — reads only that shape. A new provider is an adapter to it, never a change in the drawer
- `sanitizeOcrText` runs first inside `normalizeOcrText` and knows nothing about avize: encoding, control characters, quotes, dashes, rulers. Field vocabulary (TPO, PSL, plates) stays in the code fixes below it and in the profiles. `extractDocument` must see the same text whether it came from Mistral, `pdf-parse` or a test fixture
- **Validation is the domain's, not the OCR's.** `validateAviz.js` decides what a plausible TPO, plate, date or duplicate is; `avizFieldSchema.js` holds the confidence bands per field (critical fields stricter). A document's routing is the worst of its fields and rules. `hitl_required` cannot be confirmed without review (409 `NEEDS_REVIEW`); `force` is admin-only with a reason and is logged
- **Every correction is an event.** Both the HITL drawer (`PUT /documents/:id/corrections`) and the office form (`PUT /entities/AvizDocument/:id`, via `avizOcrFieldChanges`) write `document_events` `kind='corrected'` with `field_changes[]` (old → new, who, when), inside the transaction that made the change. `GET /documents/feedback` is built from those events; a write path that skips them makes the feedback loop lie
- **Feedback is a report, not a model.** `lib/ocr/feedback.js` aggregates and suggests; it changes nothing. Thresholds and profiles are adjusted by a person, in code, so a March report recalculates identically in April. Suggestions are only spoken past `SUGGESTION_MIN_DOCS` (10) — a 100 % rate on two documents is an anecdote
- `document_events.kind` is a CHECK list in `migrate.js`. A new kind (`review_approved` was one) must be added there with the `DROP CONSTRAINT IF EXISTS` / `ADD CONSTRAINT` pair, or the insert fails at runtime on a path the unit tests never reach
- Client-side image preparation (`src/lib/imagePreprocess.js`: EXIF orientation, downscale to 2600 px, contrast stretch only when washed out, JPEG) runs before the blur check and the size check, and **never blocks** — a file that cannot be prepared is sent as picked. Like the blur check, it is a courtesy, not a gate
- `VITE_APP_PROFILE=documents` is the RAI companion: the same codebase with the office UI trimmed to `/avize` + `/reports` (`src/lib/appProfile.js`). It is a **UI profile, not authorization** — the isolation that matters is the separate database and `JWT_SECRET`, not the hidden routes
- pg returns `DATE` columns as `Date` objects and the API returns ISO strings — date helpers must accept both
- Route schedules are built in the **server's** timezone (`route_date` + `starts_at`). Fine while everything runs in Europe/Bucharest; a company timezone setting is needed before hosting tenants elsewhere
- A report column defaults to **blank**, not `0`. `default_value: 0` on a measured field turns "we never weighed this" into "0 kg", which reads on a customer's sheet as a truck that went out empty and quietly understates the column total. Only a genuinely neutral value (one trip per aviz, the RAI annex's contractual zeros) may default to a number
- Whether a column may be summed is declared once, in `total` on `server/src/lib/reporting/sources.js`. A **rate is never summed** — ten trips at 2,50 lei/km do not make 25 lei/km, and a footer saying so is worse than no footer
- The `Anexa Factura RAI` template is a layout agreed with the customer and is locked. Never widen or reorder it to add a field: ship a **preset** in `reporting/presets.js` instead, and let `reportWarnings` say out loud when a chosen template drops a figure the documents carry (`weight_not_exported`)
- `aviz_export_log.snapshot` stores the **rendered rows**, and `GET /api/reports/exports/:id/file` renders that snapshot. A re-download must never re-read the documents: they may have been corrected since, and "roughly what we sent" is not an answer. Drift is reported separately, per document
- The extractor's field names and the document's column names are not the same vocabulary (`quantity` → `cantitate_marfa`). Corrections coming from a screen must pass through `canonicalFieldName` in `ocr/extract.js`, or the extractor's own field stays `missing` and the document can never leave review
- A normaliser must not drop part of an identifier. `normalizeTpo` once matched only the first run of digits, so every `TPO 2026-0311` of a year collapsed to `TPO-2026` — distinct trips shared one number on the annex and clean selections were flagged as duplicates
- A validation rule earns its place only by naming a concrete consequence in `validation/catalog.js`. An alert on something merely untidy trains people to ignore the ones that end in a wrong invoice, and then the whole screen is worthless
- `checkTripTariff` calls the same `findTariff` the TPO calculation calls. Reimplementing the lookup would let the alert and the invoice disagree, which is worse than having no alert at all
- A finding's `key` is its dismissal identity, shared with `office_notification_dismissals`. Bake the changing fact into the key (`tpo_stale` carries `updated_at`) so that dismissing it once does not hide the next occurrence
- Only `severity: 'error'` findings reach the notification bell; warnings live on `/checks`, where there is room to explain them. Pushing all of them into the bell buries the trip alerts it exists for
- A count in a header must be computed from the rows actually on screen. Filtering a list without recounting its summary makes the screen contradict itself, and the operator cannot tell which half is right
- Every export — `/api/reports/export`, `/api/avize/export`, email, zip — goes through `recordExport` in `reporting/exportLog.js`. Two recorders wrote different amounts of detail once, and only one of them could reproduce its own file; nobody would find that out until a customer asked for last month's sheet again
- Drift detection on an export compares `aviz_documents.updated_at` against the export time. Any write path that forgets `updated_at = NOW()` becomes invisible to the history — there is no trigger doing it for you
- A trip has **one** consignment note, in one `trip_documents` row, whichever way it came into being. `source` is `scan` or `digital`; a second table would let a photograph and a typed note disagree about what was carried, and `conflictsWithScan` is what keeps the digital form off a trip that already has a scan
- Signing a CMR validates the **merged** document server-side, never the payload. Checking only what was sent would let a client sign an empty note by posting nothing but the signature
- The weight box (11) is required to sign a loading. A consignment note without the weighbridge figure cannot be reconciled with anything downstream — TPO, report, invoice
- Driver uploads go to `/api/driver-documents` and land in the same `document_batches` queue as office scans, one batch per trip. A photo that stops at `trip_documents` never reaches OCR and never reaches a report
- `formatLocalDate`, never `toISOString().slice(0,10)`, when turning a pg DATE into a calendar day. pg hands back local midnight, and the UTC form lands on the previous day everywhere east of Greenwich — it put yesterday's date on a consignment note
- plpgsql is blocked by Application Control on the dev machine, so `DO $$ … $$` blocks fail in `migrate.js`. Add a constraint with `DROP CONSTRAINT IF EXISTS` then `ADD CONSTRAINT` — plain DDL, idempotent, no procedural language
- Route tests live beside the routes as `*.api.test.js` and run with `npm run test:api` against a real Postgres named `*_test` (`TEST_DATABASE_URL`). They are excluded from `npm test` on purpose, so a clean checkout still runs the unit suite with nothing started. `globalSetup` creates the database and migrates it with the production migration — a schema built any other way stops catching schema bugs
- Never point the route suite at a working database. The guard refuses any name not ending in `_test`, and it is not to be relaxed: the suite deletes rows and there is no undo
- Each route test file seeds its own company via `seedCompany()` and drops it after. `company_id` scoping is the isolation; there are no shared fixtures to keep in sync
- Fixture overrides use `pick(overrides, key, fallback)`, not `??`. `overrides.x ?? fallback` cannot express "explicitly nothing", and a fixture that swaps a deliberate `null` for a default makes the missing-value tests pass for the wrong reason
- `UPLOAD_DIR` sends uploads elsewhere; the route suite points it at `server/.test-uploads`. Without it fixture files pile up in a developer's real uploads folder with nothing in the database referencing them. It is read in `uploadPath.js` with its own `dotenv.config()`, because ES imports evaluate before the entrypoint's
- pg returns `NUMERIC` columns as **strings**. `prefillFromTrip` runs its output through `sanitiseCmr` for exactly this reason — a weight read straight off a trip reaches the CMR box as `"9000.00"`
- A document batch only moves forward. Background OCR must never write `extracted` over `confirmed`, or a confirmation landing mid-extraction is silently undone
- **e-Transport:** a UIT is checked at the roadside, so a placeholder must be impossible to mistake for a real code. Stub codes carry the `STUB-` prefix on the code itself — a flag beside it is lost the moment the code is printed, read out, or typed elsewhere. `ETRANSPORT_MODE=anaf` without credentials is a loud failure, never a quiet downgrade to stub. `src/lib/uit.js` mirrors the prefix for the UI and `uit.test.js` asserts the two still agree
- The e-Transport ANAF adapter has **never been run against ANAF** — there is no certificate. `buildUitDeclaration` is written to the published contract and unit-tested; the transport itself is not verified. Do not describe it as working
- The printable CMR is rasterized like the road sheet, for the same reason: standard PDF fonts cannot encode Romanian diacritics. An unsigned note must print as visibly unsigned — a page that looks like a completed CMR when nobody signed it is worse than no page
- The commercial configuration screen (`/commercial`) gets its warnings from `findTariff` and `findOverlaps` — the same functions the TPO calculation uses. A screen that decides for itself what "valid" means is how a rate reads as active on screen and is skipped in the invoice
- A tariff is never edited in place to change a price. The screen says so out loud: close the old period and add a new one from the date of the act adițional, so a March report stays recalculable with March's rate
- `vehicle_class` and `mma_kg` are both editable on the vehicle form, side by side, each with a note saying what the other is for. They were columns with no UI for a long time, which meant the very first requirement in the brief was unreachable
- The depot is refused unless the location is geocoded. Without coordinates the round trip cannot be measured and the TPO loses its kilometre component silently — a refusal is better than a depot that cannot be routed
- Observation codes are the customer's, never invented: `/commercial` imports their sheet (`Cod | Descriere | Tip | Activ`). Every unusable row is named and counted, because a silently skipped row is how half a code list goes missing
- `data_facturare` (billing date) and `data_efectuare_cursa` (trip date) are separate columns and must stay that way. Tariffs, zone rates and surcharges are all read **as of the trip date**; stamping an invoice date onto the trip date to tidy a report would silently reprice every line and make a mid-month rate change unauditable. `POST /api/reports/invoice-date` writes only the billing column
- Cell formatting in `mapAnnexRows` is driven by the source's declared `type`, not by a hard-coded column name. The moment a second date source existed, the old `col.source === 'data_efectuare_cursa'` check left it in ISO on the customer's sheet
- The driver app must survive losing signal. Every write the driver makes goes through the outbox in `src/lib/offlineQueue.js`: a failed send with no HTTP status is queued and replayed, one with a 4xx is parked and shown. The queue is FIFO and **stops at the first transport failure** — a signature depends on the draft queued before it, so skipping ahead would sign a note that has not been written
- The outbox is keyed by `user_id`. A phone gets handed to another driver, and flushing one person's unsent signatures under someone else's session would attach them to the wrong trip
- Drafts live in IndexedDB, not `localStorage`: the outbox has to be able to hold photographs, and `localStorage` caps out around 5 MB for everything combined. `offlineStore.js` swallows every storage error — a private window must degrade to "no offline support", never to a driver app that will not open
- Flush on mount as well as on the online transition. The commonest case has no transition at all: the app is closed in a dead spot and reopened in town, so the session never observes going offline
- `isOfflineError` decides by the *absence* of an HTTP status. A 422 means the tunnel worked and the server said no; only a `fetch` rejection means no connection
- Refresh tokens carry a `jti` backed by a `refresh_tokens` row, and every refresh rotates it: the old row is revoked as the new one is issued, so a leaked token is usable at most once. `POST /auth/logout` revokes; before this it returned `{ ok: true }` and did nothing at all
- Access tokens are deliberately **not** checked against the database per request — that would put a read in front of every call. The exposure window after a revocation is therefore `JWT_EXPIRES_IN`, currently 24h in `.env`. Lower it; the refresh table cannot shorten it
- A refresh token minted before the sessions table existed has no `jti` and is accepted once, then replaced with a tracked one. Rejecting them outright would have logged out every signed-in user on deploy
- Error boundaries are placed twice: per route inside `Layout`, so a broken screen leaves the sidebar usable, and once around the whole app. The per-route one resets on `location.pathname`, or navigating away would leave a dead end
- **One money path.** An invoice is built from `trip_charges` — the lines the pricing engine produced — never re-derived from `aviz_documents.valoare_tpo` or from `km × tarif`. There used to be two paths that nothing compared, so an invoice could go out on a figure nothing had recalculated. A trip with no charges is refused and named, never substituted
- Invoice components survive to `invoice_lines`, mirroring `trip_charges`. A customer disputes "why 120 for the crane", not "why 975"; a bare subtotal gives them nothing to point at
- `headerTripId` leaves `invoices.trip_id` null when a draft spans several trips. Pinning it to whichever sorted first files the document against the wrong trip
- VAT comes from `vatRateFor(company)`, not a hard-coded 19 — a company outside the VAT system must not have it added
- **Retention has a protected list.** `lib/maintenance/retention.js` prunes telemetry and caches only. A record of what we sent a customer (`aviz_export_log`), or of what a person did (`document_events`), is never pruned — nor are `trip_charges`, `invoice_lines`, `delivery_proofs`, `trip_documents`. A unit test asserts the two lists never meet
- One policy declares one `where`; the count and the delete are both built from it, so a preview can never describe something different from what the run removes
- Every delete is batched and holds an advisory lock. An unbounded `DELETE` over millions of rows takes a long lock and bloats the table; two instances deleting at once fight over the same pages
- Schedulers start in `index.js`, never in `app.js` — mounting the app with supertest must not start a timer that deletes rows under the suite
- **The audit trail has an explicit list, both ways.** `lib/audit/events.js` names what is audited and what is not, each with a reason. A row per GPS ping would bury the entries that matter and undo the retention policies; `AvizDocument` stays off it because `document_events` already covers it in more detail. A unit test asserts nothing is on both lists
- The diff is taken against the stored rows, never the request payload, so a value the server derived (`distance_source`, an allocated invoice number) is recorded too. An update that changed nothing writes no event
- Secret values are redacted by pattern (`SECRET_FIELD`), not by a list of column names. Over-redacting is a small annoyance; a leaked password hash in a table built for people to read is not
- The audit write goes inside the transaction that made the change. A trail with silent gaps is worse than none, because a gap cannot be told apart from nothing having happened — but the write never fails the request: the business change has already succeeded by then
- `user_name` / `user_email` are denormalised on the event. `user_id` is `ON DELETE SET NULL`, which would otherwise erase the one fact the row exists to record
- `entity_id` carries no foreign key: it is polymorphic, and a delete — the event most worth keeping — would take its own trail with it
- **Nobody keeps a password somebody else chose.** An invitation creates the account with a hash seeded from random bytes and sends a link; the person chooses their own password through the existing reset flow. The one exception is `POST /users/manual`, for somebody who cannot open an email: the admin sets (or is given) a *temporary* password, the row gets `must_change_password`, the access token carries `pcr`, and `authRequired` refuses everything outside `/api/auth/` until `POST /auth/change-password`. Hiding screens in the browser is not the enforcement; the middleware is. The temporary password never reaches the audit trail and is returned only when the server generated it
- **One address, one account, across every company.** Login looks an email up globally, so `/auth/register`, `/auth/google`, `/users/invite` and `/users/manual` all refuse an address used in *any* company. `users` is only `UNIQUE (company_id, email)` in the schema, so the check lives in code
- **Self sign-up waits on its link.** `/auth/register` returns no tokens; `created_via = 'signup'` rows cannot log in until `/auth/verify-email`. Only that value is gated: invited people prove the mailbox by setting a password from the link, manual accounts are vouched for, and rows written by seed scripts have no `created_via`. The baseline backfill marks only `created_via IS NULL` rows verified, because it runs on every start
- Verification tokens are stored as a SHA-256 hash (`email_verify_token_hash`); the plaintext exists only in the email
- **Company domain, not personal domain.** `lib/auth/signup.js` lists free mailbox providers; `src/lib/emailKind.js` mirrors it and a test compares them. A company address whose domain already has active users makes sign-up answer `409 DOMAIN_IN_USE` until the person confirms (`confirm_domain: true`) — a colleague registering instead of asking for an invitation creates an empty company beside the real one. A personal domain is never that signal
- **Google sign-in verifies the ID token on the server** (`lib/auth/google.js`: Google's certificates, `aud = GOOGLE_CLIENT_ID`, issuer, expiry, `email_verified`). Unset `GOOGLE_CLIENT_ID` is a 503 and a hidden button, never "accept any audience". An existing address signs in and gets `google_sub`; a different `sub` on the same address is refused. A new address answers `404 GOOGLE_NEEDS_COMPANY` until a company name is sent. Route tests mock the module — no test calls Google
- **Links in account emails use `CLIENT_ORIGIN`, not the request's `origin`** (`lib/auth/mail.js`). With `CLIENT_ORIGIN` set, a browser-sent origin is used only if it is on that list; otherwise a reset requested for somebody else's address could deliver their token to any host. `ALLOW_SIGNUP=false` closes self sign-up (register and Google) for an invitation-only deployment
- **Nobody is deleted.** `users.id` is on `audit_events`, `refresh_tokens` and `drivers`. Deactivation (`is_active = false`) is the operation; the history stays
- The last active admin cannot be demoted or deactivated, and nobody may change their own role or switch themselves off. A company that does either loses user administration, tariffs and the audit trail at once, and the only way back is SQL
- Deactivating and changing a role revoke every session. An access token already issued keeps working until `JWT_EXPIRES_IN` — the response returns that value so the screen can say so instead of implying the cut is instant
- A `driver` account with no `drivers.user_id` link signs in to an empty app: trips resolve through that column. The list flags it rather than letting somebody find out on the road
- `sendEmail` resolves happily with no provider configured (`{ stub: true }`). Treat a stubbed send as **not sent** and hand the caller the link, or an admin waits for an email nobody will receive
- **Schema changes go in `server/src/migrations/NNNN_name.sql`, never in the `migrate.js` baseline.** The baseline runs once and is then skipped; a statement added to it runs on every deploy forever, which is fine for `IF NOT EXISTS` and quietly wrong for anything else. Write `NNNN_name.down.sql` beside it wherever the change can be undone — `migrate:down` refuses rather than guessing when there is none
- A migration file whose name does not match the shape, or that shares a number with another, is an error rather than something skipped. One silently ignored is the worst outcome available
- **Use the structured logger, not `console`** — `createLogger({ scope })` at module level. `AsyncLocalStorage` stamps the request id onto every line, so a logger three files deep from the route is still traceable. `log.error(msg, err)` takes the error separately so the stack survives. CLI scripts (`seed`, `backfill-*`, `geocode-*`, `migrate`) keep `console` on purpose: they talk to a person at a terminal
- Never log a request body. Log who, never what they sent — that is where the passwords are. Field names are redacted by pattern in `sanitise`, but the rule is not to pass them in the first place
- On this branch the password rule lives in `server/src/lib/auth/signup.js` (`passwordProblem`: 10+ characters, no edge spaces, not containing the email) and is mirrored by `src/lib/emailKind.js`; `main` has `lib/password.js` — fold them together on merge
- **One password policy, in `lib/password.js`** — length plus a blocklist, no composition rules. Requiring an uppercase, a digit and a symbol is what produces `Parola1!` on every account; it measures compliance, not resistance to guessing. `src/lib/passwordPolicy.js` mirrors the minimum for the browser and a test compares the two, the same arrangement as the UIT prefix
- Helmet is configured with CSP off (this process serves an API and uploads, not the app HTML) and HSTS only under `NODE_ENV=production`. A header sent where it cannot apply is one nobody can reason about
- **`docs/manual/` is the end-user manual** (Romanian). When a change alters what a screen does, what a rule refuses, or a number a user is told (retention windows, token lifetimes, password minimum, confidence thresholds), update the matching chapter in the same change. A manual that describes last month's behaviour is worse than none: people act on it
- Every chapter answers the same four questions — what it does, how you work in it, what outcome we track, what can go wrong. Keep that shape
- Do not reintroduce Base44 SDK, plugins, or references
- **Responsive:** office UI must work from ~360px (phone) through tablet to desktop. Prefer card layouts under `md`, tables from `md` up with `overflow-x-auto` + `min-w-*`. Do not hide critical actions only behind desktop-only UI.

## Documentation & versioning (mandatory for all agents)

Until a better permanent location is chosen, document **every meaningful change locally** before considering work done.

1. **Changelog companion RAI** — HTML + PDF în `docs/CHANGELOGS/`:
   - **La fiecare „commit și push”**: bump obligatoriu `companion.version` + `companion.build` în root `package.json` (orice branch), apoi append în changelog; commit cu `[skip version]`. Excepție doar dacă utilizatorul zice explicit „fără bump”.
   - Mirror de la v1.8.3 / build 62; **Changelog #1 deschis** (builds **63+**): `ChangeLog-demo-experimenting-RAISpedition-01-builds-63.html` — **Changelog** + **Bugfix** per build; append până când utilizatorul zice gata.
   - La închidere: PDF + redenumire `…-01-builds-63-<ultimulBuild>.html` (ex. `…-63-70`) + mutare în `old/`.
   - Istoric RAI (înainte de demo): `docs/_archive-RAI-spedition-driver-app-changelogs/` (local).
   - **Nu** `changelogsSprints/` (Transitix TMS full).
2. **`docs/changes/`** — note scurte per increment. **Tot `docs/` e gitignored** (inclusiv changelog-urile) — rămân doar local, nu pe GitHub.
3. **Semver** — Keep root `package.json` and `server/package.json` versions aligned. A `post-commit` hook (`scripts/semver-post-commit.js`, installed via `npm run prepare`) bumps both from the commit message: `feat:` → minor, `feat!:` / `BREAKING CHANGE` → major, otherwise patch. Add `[skip version]` to skip. The UI reads this version (`src/lib/appVersion.js`).
 - **patch** — fixes, docs, tooling
 - **minor** — user-visible features
 - **major** — breaking API/schema
4. Do not leave undocumented behavior, API, or schema changes.
